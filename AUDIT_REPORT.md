## 2. P0: Анализ критических проблем и внедрённые исправления

### 2.1. Безопасность семейного кода и защита от перебора
- **Проблема:** Семейный 6-значный код (например, `HAUS-1234`) при отсутствии rate-limiting и блокировок мог быть подвержен брутфорс-перебору скриптами.
- **Внедрённое исправление в `server.ts`:**
  - Реализован встроенный **Brute-Force Shield (`syncBruteForceProtection`)**.
  - При 8 неудачных попытках ввода несуществующего кода с одного IP-адреса, данный IP автоматически **блокируется на 15 минут** с возвратом статуса `429 Too Many Requests`.
  - Введена строгая валидация формата семейного кода (`/^[A-Z0-9-]{4,16}$/`), отсекающая любые инъекции и спецсимволы.
  - Установлен лимит на размер полезной нагрузки состояния домохозяйства (максимум 25 МБ, статус `413 Payload Too Large`).

### 2.2. Утечка Gemini API Key: проверка бандла и изоляция
- **Проверка исходного кода:**
  - Проверено: переменная `GEMINI_API_KEY` считывается **исключительно в `server.ts`** через `process.env.GEMINI_API_KEY`.
  - В файле `vite.config.ts` и в директории `src/` отсутствуют переменные с префиксом `VITE_GEMINI_API_KEY`.
  - Клиентский код (`src/services/aiService.ts`, `src/services/geminiReceiptService.ts`) обращается только к локальным серверным прокси-маршрутам `/api/ai/*`.
  - **Вывод:** Ключ Gemini API **не попадает** в клиентский bundle, исходный код браузера или source map.

### 2.3. Защита API: Rate Limiter, валидация и заголовки
- **Внедрённое исправление в `server.ts`:**
  - Добавлен **AI Rate Limiter (`aiRateLimiter`)**: не более 30 запросов в минуту с одного IP на `/api/ai/parse`, `/api/ai/parse-receipt` и `/api/ai/import-recipe`.
  - Установлены заголовки безопасности HTTP:
    - `X-Content-Type-Options: nosniff` (защита от MIME-sniffing).
    - `X-Frame-Options: SAMEORIGIN` (защита от Clickjacking).
    - `Referrer-Policy: strict-origin-when-cross-origin`.

### 2.4. Медицинская и юридическая ответственность в SOS и Аптечке
- **Проблема:** Ошибочное восприятие приложения как медицинского сервиса может повлечь риски для здоровья пользователей при ЧС.
- **Внедрённое исправление:**
  - В компонент `src/components/sos/SOSView.tsx` добавлен явный **Юридический и медицинский дисклеймер**:
    > *«⚠️ Важное предупреждение о безопасности и медицинской ответственности: Информация в этом разделе носит исключительно справочный характер для семьи. При непосредственной угрозе жизни, здоровью, признаках инфаркта, инсульта, тяжелых травмах или пожаре немедленно звоните в государственные службы спасения (112 / Скорая помощь). Всегда сверяйте и актуализируйте аллергии, группы крови и дозировки медикаментов у вашего лечащего врача.»*
  - В компонент `src/components/firstaid/FirstAidView.tsx` добавлена карточка **Медицинской оговорки**:
    > *«Медицинская оговорка: Приложение предназначено исключительно для учёта сроков годности и домашнего инвентаря. Не используйте информацию из приложения для самолечения. Всегда консультируйтесь с лечащим врачом или фармацевтом перед приёмом лекарственных препаратов.»*

### 2.5. Конфиденциальность AI и OCR: обработка данных
- **Фактическое поведение в кодовой базе:**
  - **Чеки:** Пользователь может сканировать чеки **100% локально** с помощью автономного движка Tesseract.js прямо в браузере (без отправки на сервера). Перед сохранением любого чека открывается окно **`ReceiptReviewModal`**, где пользователь вручную подтверждает или корректирует каждую позицию, цену и категорию.
  - **AI-разбор:** При отсутствии `GEMINI_API_KEY` или при работе без интернета данные никуда не отправляются: работает локальный синтаксический анализатор `parseWithRuleEngine`.
  - **Логирование:** В `server.ts` убран вывод личных данных (названий купленных товаров, сумм чеков, телефонных номеров). В логах фиксируется только обезличенный факт вызова (`items count: N`).

### 2.6. Риск потери локальных данных (IndexedDB / LocalStorage)
- **Архитектурный факт:** Браузерные хранилища (IndexedDB/LocalStorage) могут быть очищены пользователем при нажатии «Очистить историю браузера» или при критической нехватке памяти на iOS Safari.
- **Механизмы защиты в приложении:**
  1. В модуле **Настройки** реализована кнопка **«Экспорт резервной копии» (JSON Backup)** — скачивается полный файл со всеми задачами, рецептами, чеками, аптечкой и документами.
  2. Облачная семейная синхронизация сохраняет копию состояния на сервере.
  3. Для продакшн-эксплуатации пользователю рекомендуется периодически выгружать JSON-бэкап.

### 2.7. Модель конфликтов синхронизации
- **Текущая модель:** Last-Write-Wins (LWW) на уровне всего объекта домохозяйства с фиксацией метки времени `updatedAt`.
- **Ограничение:** При одновременном редактировании с двух разных устройств в одну и ту же секунду сохраняется последняя отправленная версия.
- **Рекомендация для будущего развития:** Реализация пообъектного слияния (CRDT или версионирование по сущностям с `entity_version`).

## 3. P1: Архитектура, API, Cloud Run и эксплуатация

### 3.1. Cloud Run vs Локальные файлы data/families
- **Важное архитектурное различие:**
  - В **Docker / Docker Compose** и на **Linux VPS** данные сохраняются гарантированно благодаря монтированию постоянного тома (`volume: onehaus_family_data:/app/data/families`).
  - В бессерверных контейнерах **Google Cloud Run** файловая система является *эфемерной (stateless)*. При масштабировании до 0 или перезапуске контейнера локальные файлы сбрасываются.
  - **Рекомендация:** Для постоянного облачного продакшна в Google Cloud использовать Cloud SQL (PostgreSQL), Firebase Firestore или монтирование Cloud Storage FUSE.

### 3.2. Healthcheck & Readiness endpoint
- **Внедрённое исправление в `server.ts`:**
  - Добавлен официальный endpoint `GET /api/health`:
    ```json
    {
      "status": "ok",
      "service": "onehaus-family-app",
      "uptimeSeconds": 1420,
      "timestamp": "2026-10-30T10:30:00.000Z",
      "aiConfigured": true
    }
    ```
  - В `Dockerfile` директива `HEALTHCHECK` обновлена для вызова `http://localhost:3000/api/health`.

### 3.3. Каскад моделей Gemini и автономный Rule Engine fallback
- **Проверка в коде (`server.ts`):**
  - Реализован каскад моделей `callGeminiWithFallback`: сначала опрашивается `gemini-3.8-flash`, при таймауте или ошибке — `gemini-3.5-flash`, затем `gemini-3.1-flash-lite`.
  - При полной недоступности внешнего API или отсутствии ключа сервер моментально возвращает результат работы автономного Rule Engine без падения запроса (HTTP 200).

### 3.4. Санитизация ввода и защита от Prompt Injection
- **Внедрённое исправление в `server.ts`:**
  - В `/api/ai/parse` длина текста ограничена 4 000 символов (`text.slice(0, 4000)`).
  - В `/api/ai/import-recipe` длина URL ограничена 1 500 символов, а скачанный текст — 6 000 символов.
  - Исключена передача неконтролируемых гигантских объёмов текста в контекст нейросети.

### 3.5. Очистка логов от персональных данных (PII)
- В `server.ts` удалены `console.log` с выводом содержимого чеков, названий магазинов и сумм.
- При ошибках внешних сервисов клиенту не отдаются системные стеки вызовов (stack traces).

### 3.6. Поведение PWA и Service Worker на iOS/Android
- **PWA Manifest:** настроен `standalone`, с иконками 192x192, 512x512 и `maskable`.
- **iOS Safari Safe Area:** в стилях предусмотрены отступы под системный Home Indicator и вырезы Dynamic Island (`pb-20 md:pb-0`, адаптивный Header).
- **Service Worker Lifecycle:** в dev-режиме устаревшие SW автоматически дерегистрируются, в production настроена автоматическая активация (`skipWaiting: true`, `clientsClaim: true`).

1. **История изменений (Audit Log / Activity Feed):** сохранение истории последних 50 действий (кто выполнил задачу, кто вычеркнул покупку).

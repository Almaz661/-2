## 2. Спецификация серверных API эндпоинтов

Сервер реализован на Express в файле `server.ts`. Все эндпоинты поддерживают лимит тела запроса до 50 МБ для работы с фотографиями чеков высокого разрешения со смартфонов.

### 2.1. Геолокация: `GET /api/detect-location`
Автоматически определяет город и координаты клиента по IP адресу (для автонастройки виджета погоды без всплывающих окон запроса геолокации).
- **Метод:** `GET`
- **Ответ (200 OK):**
  ```json
  {
    "id": "server_geo_1730000000",
    "name": "Москва",
    "country": "Россия",
    "latitude": 55.7558,
    "longitude": 37.6173
  }
  ```

### 2.2. Семейная синхронизация: `POST /api/family-sync/push`
Отправляет текущее состояние домохозяйства на сервер для синхронизации с другими устройствами семьи.
- **Метод:** `POST`
- **Тело запроса:**
  ```json
  {
    "familyCode": "HAUS-7821",
    "data": {
      "householdName": "Семья Ивановых",
      "members": [...],
      "tasks": [...],
      "events": [...],
      "shoppingLists": [...],
      "shoppingItems": [...],
      "recipes": [...],
      "medicines": [...],
      "utilityMeters": [...]
    }
  }
  ```
- **Ответ (200 OK):**
  ```json
  {
    "success": true,
    "updatedAt": "2026-10-30T10:15:30.123Z"
  }
  ```

### 2.3. Семейная синхронизация: `GET /api/family-sync/pull/:code`
Получает актуальное состояние домохозяйства с сервера по семейному коду.
- **Метод:** `GET`
- **Параметр маршрута:** `:code` — 6-значный буквенно-цифровой код семьи.
- **Ответ (200 OK):**
  ```json
  {
    "familyCode": "HAUS-7821",
    "updatedAt": "2026-10-30T10:15:30.123Z",
    "data": { ... }
  }
  ```
- **Ответ (404 Not Found):** `{"error": "Семья с таким кодом не найдена"}`

### 2.4. Интеллектуальный ввод: `POST /api/ai/parse`
Распознает свободный текст, голосовую расшифровку или прикрепленное фото и преобразует в структурированные действия приложения (задачи, события календаря, покупки, контакты, документы).
- **Метод:** `POST`
- **Тело запроса:**
  ```json
  {
    "text": "Купить сметану 20% 2 пачки и хлеб завтра утром",
    "members": [{ "id": "1", "name": "Ольга", "role": "Мама" }],
    "imageBase64": "data:image/jpeg;base64,..."
  }
  ```
- **Логика обработки:**
  1. Если настроен `GEMINI_API_KEY` — вызывается модель Gemini с каскадом отказоустойчивости (`gemini-3.8-flash` -> `gemini-3.5-flash` -> `gemini-3.1-flash-lite`).
  2. Если ключ не задан или возник сбой сети — **автоматически включается встроенный Rule Engine**, который мгновенно извлекает сущности по регулярным выражениям и шаблонам.
- **Ответ (200 OK):**
  ```json
  {
    "summary": "Распознаны покупки в список Супермаркет",
    "actions": [
      {
        "type": "shopping",
        "title": "Сметана 20%",
        "details": "Категория: dairy, количество: 2 пачки",
        "data": {
          "title": "Сметана 20%",
          "quantity": "2 пачки",
          "category": "dairy",
          "listId": "list-supermarket"
        }
      },
      {
        "type": "shopping",
        "title": "Хлеб",
        "details": "Категория: bakery, количество: 1 шт.",
        "data": {
          "title": "Хлеб",
          "quantity": "1 шт.",
          "category": "bakery",
          "listId": "list-supermarket"
        }
      }
    ]
  }
  ```

## 3. Архитектура клиентских хранилищ (Storage Architecture)

Для обеспечения максимальной скорости и автономности используется двухуровневое клиентское хранилище:

| Хранилище | Технология | Назначение | Преимущество |
|---|---|---|---|
| **Быстрое состояние** | `LocalStorage` | Активная вкладка, фильтры, код семьи, базовые списки покупок | Мгновенный синхронный доступ при старте компонентов |
| **Оффлайн БД задач и событий** | `IndexedDB` (`onehaus_offline_db`) | Все задачи, события календаря, история изменений | Отсутствие лимита в 5 МБ, надёжная транзакционность |
| **Фотоархив чеков** | `IndexedDB` (`onehaus_receipt_photos_db`) | Base64 и бинарные изображения чеков | Сжатие изображений, не замедляет работу интерфейса |

### Схема базы `onehaus_offline_db`:
- **Store `tasks-store`:** ключ `id`. Индексы: `assigneeId`, `dueDate`, `completed`.
- **Store `events-store`:** ключ `id`. Индексы: `date`, `category`.

### Схема базы `onehaus_receipt_photos_db`:
- **Store `receipt-photos-store`:** ключ `id` (соответствует ID чека). Поле `photoBase64`.

## 4. Конфигурация PWA и Service Worker

Сервис-воркер настроен с помощью плагина `vite-plugin-pwa` и библиотеки `workbox`:
- **Режим кэширования статики:** `CacheFirst` для шрифтов Google Fonts (`https://fonts.googleapis.com` и `https://fonts.gstatic.com`). Время жизни кэша: 1 год.
- **Кэширование погодного API:** `NetworkFirst` с таймаутом сети 3 секунды для Open-Meteo (`https://api.open-meteo.com`). Если интернет отсутствует, приложение моментально отображает последний сохраненный прогноз погоды.
- **Стратегия обновления:** `autoUpdate` + `skipWaiting: true`, `clientsClaim: true` — новые версии приложения подхватываются без зависания на старых файлах.
